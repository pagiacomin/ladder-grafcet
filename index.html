Interactively Converting Ladder Diagrams into Grafcet Diagrams on a Robotic Neutralisation System Case Study


This webpage is a complementary material about the paper having the same title published in the Journal on Interactive Systems in 2026. While the paper focuses on the algorithm and its time complexity, this page is concentrated on the interactive system, which is a proof of concept version.

 The system begins by loading the XML file containing the ladder diagram and by showing it to the expert by means of a graphical interface, as shown below. This diagrams' purpose is to control the robotic neutralisation system described in the paper, which is considered as a realistic case study. For more details, see the videos at this same github page.

 

       

Afterwards, the paper identifies rungs that do not have a seal, which can be considered a condition action or part of a rung with a seal, which could be considered a step. After the identification, the system asks the expert system for confirmation, as shown below.

 

 Once the condition actions are identified, the next phase consists of detecting the possible states following the initial state. The system identifies as possible candidates those having a seal or those which are confirmed as steps in the previous phase. The figure below shows these possible states identified for the robotic neutralisation system.

 


        Afterwards, the system tries to identify the next steps following the steps confirmed in the previous phase. This is made with the help of Binary Decision Diagrams (BDD), as explained in the paper. However, not every step is confirmed as a real next state. On the left, the system shows the original rung, below the possible next rungs, which will be converted into steps of the Grafcet diagram, and on the right, there are two important pieces of information. Firstly, on top, the system asks the expert for information on the kind of transition from the source step to the target steps. Disjunctions create a transition from one step to several other steps, while a junction creates a transition from several steps to only one step. However, in the case of junction transitions, only one target step must be informed at once. Secondly, on the bottom, the system asks the expert to inform about possible next steps not detected on the left. In this case, the expert must inform the transition condition, the next step, which can be represented by a coil or an auxiliary step, and the step's instance in the diagram. The instance is necessary because one step can occur several times in the Grafcet diagram, where each one must have a different instance number, as shown below.

 

 

 Above, the initial state is represented by the character S. Alternative or concurrent paths are represented by arcs OR or AND, see the paper for details. Below, it is possible to see that auxiliary steps can also be considered source steps.

 

 As can be observed above, the system did not identify the next possible steps because the source step still does not have a deactivation condition. In this case, such conditions will be determined by the activation conditions of the next steps. The figure below shows the resulting Grafcet diagram. The figure is intentionally compacted due to the space available; see the video on the same GitHub site for more details.

 

 

 The layout of the graph above was not produced by the system itself, but by the software Neato, which produces a DOT file representing a graph as below. A possible future work could be developed with the objective of improving the layout.
